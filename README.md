# GOAT MUSIC: ロリポップ連携

GitHub Actions からロリポップに SSH 接続するための、手動の接続確認です。
対象は `goatmusic.jp` だけです。記事・設定・プラグイン・テーマの変更や定期実行は含みません。
AI/API の利用はありません。GitHub Actions の利用枠・料金は契約に依存します。

## 初回設定

このリポジトリの Settings → Secrets and variables → Actions → New repository secret に登録します。

| Secret | 内容 |
|---|---|
| `LOLIPOP_SSH_PASSWORD` | ロリポップの SSH パスワード |
| `LOLIPOP_KNOWN_HOSTS` | 接続先を検証済みの OpenSSH known_hosts エントリー |

秘密情報をチャット、コミット、ログに貼らないでください。

Mac のローカルターミナル（SSH 接続先ではない側）で、既存の公開ホスト鍵を取り出せます。

```bash
ssh-keygen -F '[ssh.lolipop.jp]:2222' -f "$HOME/.ssh/known_hosts"
```

`#` で始まらない鍵の行を `LOLIPOP_KNOWN_HOSTS` に登録します。ハッシュ化された行も対応します。
既存ファイルにあることだけでは接続先の真正性を証明しません。初回接続時の検証状況が不明な場合や警告がある場合は、
ロリポップの公式案内・サポート等の別経路でフィンガープリントを確認してください。
`ssh-keyscan` の結果を未検証のまま信頼したり、ホスト鍵検証を無効にしたりしません。

以前の `server gave bad signature for RSA key` は追加ホスト鍵の通知処理に関係する可能性がありますが、原因は未確定です。
このワークフローは登録済み鍵で接続先を厳密に検証し、追加鍵の自動登録は行いません。
接続先の鍵検証が失敗した場合は停止します。

## 接続確認

Actions → Lolipop connection check → Run workflow を実行します。
成功時は `SSH connection: OK` と PHP・WordPress のバージョンが表示されます。
これは SSH 接続とバージョン読み取りの検証であり、自動更新の設定完了を意味しません。

この方式はサーバー内で保存する認証情報や常駐プロセスを必要としません。
SSH の権限はサイト単位に制限されておらず、同一アカウントの他サイトにも届くため、
リポジトリの書き込み権限と Actions の実行権限は信頼できる担当者に限定してください。
Secrets 設定前にリポジトリの公開範囲とアクセス権を確認してください。

## 次の段階

接続確認後、指示された編集・更新を実行するワークフローを別途追加します。
現時点では本番サイトの編集、テーマ更新、cron 登録を一切自動化していません。

## セキュリティ点検

Actions → **Lolipop security audit** → Run workflow で点検できます。
同じ SSH Secrets を使い、サーバーに点検ファイルを保存せず、標準入力で読み取り専用 PHP を実行します。
WordPress の SHORTINIT でDB設定を読み、通常のプラグイン・テーマやcronは起動しません。
ただし WordPress の bootstrap が必要とする drop-in 等の副作用まで保証する方式ではありません。

- 全プラグイン・テーマ（無効なものを含む）、主要設定、更新cronの予定を収集。
- WordPress.org の更新APIと照合。製品名・バージョン等の構成情報を同APIに送信します。
- WPVulnerability の公開APIで既知脆弱性・公開停止を照合。検査対象slug/バージョンを使用します。
- 未収録、APIエラー、未解釈の範囲は「未確認」とし、安全と判定しません。
- 結果は実行の Summary とログに出力。公開リポジトリなので構成情報も公開され得ます。
  認証情報、ユーザー名、キー・saltの値、DB接続先、設定ファイルの内容は出力しません。
- バージョン範囲一致は攻撃成功の確認ではありません。MFA・WAF・復元・動作互換性の検査は別途必要です。
- 脆弱性該当・公開停止の検出、または照合未完了の場合はジョブが失敗状態になります。Summaryで両者を区別します。

本ワークフローは更新を行いません。互換性と復旧手段の未確認時には更新しないという運用です。
テーマ Abletone には既知の直接編集があるため、カスタマイズ保全と動作確認なしで更新しません。

## 保守（明示的な手動実行）

**Lolipop conservative maintenance** は `apply=false` が初期値です。
`apply=true` を選んだときだけ、固定した候補の未使用製品と管理画面ファイル編集禁止を適用します。

- 対象は WPForms Lite と WordPress 標準 Twenty 系テーマ。使用中の製品、想定外の版、公式旧版との差分がある製品はスキップします。
- パッケージは WordPress.org のHTTPS配布元からTLS検証を有効にして取得。ZIPのパス・symlink・版とPHP構文を検査します。
- オリジナルは `~/goat-maintenance-private/` 配下（0700、Web公開領域外）へ保存。設定ファイルも変更前に保存します。
- 元ファイルとDBの有効化設定が変化していないことを確認してから交換。各更新後に主要4ページのHTTP・タイトル・画像/フォーム数を比較します。
- 検証失敗時は、その対象を元に戻します。表示のピクセル比較やメール送信の検査ではありません。
- サイト全体のバックアップ・復元検証を代替しません。バックアップとマニフェストは自動削除しません。
- 使用テーマAbletone、有効プラグイン、記事、メニュー、DB設定の更新は含みません。
- `DISALLOW_FILE_EDIT` が未定義なら `wp-config.php` に `true` を追加。管理画面のコードエディターを止めるもので、記事編集・通常の更新機能は維持します。
- 既存の明示設定、CSP/HSTS、テーマ配色、脆弱な最新情報プラグインは書き換えません。
